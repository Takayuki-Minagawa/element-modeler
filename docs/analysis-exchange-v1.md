# 解析原本の関連保存・往復連携（CAD schema 16）

「解析 → 解析原本の往復連携」から解析JSONを関連付け、CADと一緒に保存できます。
節点ID・同座標の別節点・ゼロ長ばね・材端条件・MPC・任意の荷重ケース・
組合せ・単位・追加フィールドを、元のJSON値のまま再出力します。

これは解析原本の保管と再出力です。CAD形状への逆変換、CAD編集の解析原本への
自動反映、CADと原本の力学的な一致の証明は行いません。読込時のCAD構造に
関連付けて保存し、後で構造が変わった場合に不一致を検出します。

## 操作

1. 対応するCADを開き、「解析原本の往復連携」で解析JSONまたは交換JSONを読み込む。
2. 形式・単位・節点数・要素数・ばね数・拘束数・ケース数・組合せ数を確認する。
3. 通常のCAD保存で原本も保存する。解析原本だけでも自動保存の対象となる。
4. 「元の解析JSON」を保存し、元の解析プログラムで検査・実行する。
5. 「交換JSON」は原本とCAD関連情報の保管・移送に使う。

CADを変更して不一致になった場合、元の解析JSONの出力を停止します。交換JSONは
引き続き保管できます。不一致の交換JSONを読み直しても関連を更新しません。
Undoで元のCAD構造へ戻れば再び出力できます。CADを変更して解析を更新する場合は、
解析プログラムで内容を更新・確認し、更新済みの解析JSONを新たに読み込みます。

関連付けと解除はUndo/Redoできます。CAD保存・自動復元にも関連情報を保持します。
原本を含まない旧CADの読込では以前の関連を解除します。モデル置換もUndo可能です。
非同期の読込・出力中にCADや関連データが変更された場合、その処理を適用しません。

## 形式

CAD schema 16は、従来のフィールドに `analysisExchange` を追加します。
未関連は `null`。schema 1〜15のCADも読み込めます。schema 16を扱えない旧版へ
保存し直すと原本が失われる可能性があるため、対応版または交換JSONを使用します。

```json
{
  "format": "element-modeler-analysis-exchange",
  "version": 1,
  "sourceCad": {
    "fingerprintVersion": "cad-structural-json-v1",
    "fingerprint": "sha256:<64桁の小文字16進数>"
  },
  "modelFormat": "fem-struct-pygo-v1",
  "model": {
    "schema_version": "1",
    "model": {},
    "load_cases": [],
    "load_combinations": [],
    "units": { "length": "m", "force": "N", "time": "s" }
  }
}
```

上記はフィールド構成の説明であり、空の `model` は実行用サンプルではありません。
`modelFormat` は次のいずれかです。

| modelFormat | modelの識別 | 用途 |
|---|---|---|
| `element-modeler-analysis-v2` | `format: "element-modeler-analysis"`, `version: 2` | 既存の解析JSON v2原本 |
| `fem-struct-pygo-v1` | `schema_version: "1"` | FEM-Struct-PyGoの明示接続・明示参照を持つモデルbundle |

読み書きでIDを振り直さず、配列順・数値・符号・単位・座標軸・未知フィールドを保持します。
JSONの空白、キーの字句順、`1.0` と `1` の表記等は保存対象ではありません。
例えばFEM-Struct-PyGoの2Dモデルのm・N・Y鉛直はそのままです。CADのmm・Z鉛直へ
変換しません。同じ座標の節点を統合せず、要素の分割・追加も行いません。

## 入力検査と境界

識別子/バージョン、JSONの有限数値、IDの重複と参照先、単位宣言、支持・拘束の
自由度範囲、荷重ケースと組合せ係数の参照を検査します。未知フィールドは保持します。
物理的な妥当性、安定性、釣合、各要素の剛性式、解析プログラムでの対応範囲は
確認しません。件数表示や読込成功は「解析可能」「設計確認済み」を意味しません。

FEM-Struct-PyGoは明示的な節点・要素・支持・荷重の参照を対象とします。
selectorによる支持/荷重の展開や `thin_walled_members` の自動生成はここでは
実施しません。必要な場合は元のプログラム側で展開し、明示参照のJSONを渡します。
要素型などの追加フィールドは削除せず、解析能力の判定は元のプログラムに委ねます。

## CADとの関連判定

`cad-structural-json-v1` は、CADの節点・部材・面材・荷重・支持・レベル・組合せ・
解析設定と、既存v2出力で解決した使用中の材料・断面・ばね等をSHA-256で照合します。
節点統合前のCAD座標も対象です。数値は既存の `typed-json-binary64-v1` と同じ
バイナリ64表現、オブジェクトはキー順整列、配列は順序を保持してハッシュ化します。

原本自身、スキーマ番号、ファイル名、生成日時、カメラ・選択・表示設定、通り芯・下図を
除外します。現形式で表示・注記専用の `color` / `label` / `memo` / `isDefault` も
除外します。配列順やレベル名なども保守的に比較するため、力学的に同値でも不一致に
なる場合があります。これは意味的等価性の判定や電子署名ではありません。

新規の解析JSONを読む場合だけ現在のCADへ関連付けます。交換JSON、CADファイル、
Undo/Redo、自動復元に含まれる既存の `sourceCad` は再計算して置き換えません。
将来、構造フィールドや照合規則を変える場合はfingerprintVersionを更新し、
既存の関連を誤って一致と判定しないようにします。

## 既存の連携との関係

従来の「解析JSON」「解析CSV」は、引き続き現在のCADから生成します。
解析原本の往復連携は専用の入口と出口を使い、保存した原本で従来の出力を置き換えません。
交換JSONはsolver入力ではありません。solverには専用機能から再出力した元のJSONを
渡してください。既存v2用のPython adapterはこのwrapperを受け付けません。

CAD編集から原本を自動更新する相互変換や、原本のばね/MPCをCAD上で編集・描画する
機能は含みません。これらには座標軸・単位・材端・自由度・荷重規約の明示的な変換仕様が
別途必要です。
