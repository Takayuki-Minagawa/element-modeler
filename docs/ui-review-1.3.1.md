# UI・リファクタリング再点検（v1.3.1）

平面入力による部材生成を中心に、実際の操作とコードの責務を確認した。
優先度が高かったのは、ボタン・選択欄・キーボードの状態変更処理の重複と、表示設定による入力画面の混雑だった。

## 確認した不具合と修正

| 操作・問題 | 修正後 |
| --- | --- |
| Ctrl+SやIME変換中のSで支点ツールに切り替わる | 修飾キー・IME・文字入力・モーダル内の操作を共通判定で保護 |
| 3D表示中にMキーで線材を選んでも平面に戻らない | ボタン・選択欄・キーを同じツール変更処理に統一 |
| 入力途中にキーボードでUndoすると未確定の始点が残る | ボタンとキーが共通の履歴復元処理を使用し、未確定入力を解除 |
| 荷重入力をUndoした後、実際の種別と選択欄が異なる | 状態から荷重種別の選択欄も再同期 |
| 言語変更で集計からチェックへ勝手に移る | 診断の再描画とタブを開く操作を分離 |
| 外壁の案内とEnter確定が実際のポリライン入力と一致しない | 入力方式の判定を描画処理と案内で共用 |
| Ctrl+Shift+Zの大文字Zを認識しない | 履歴キーの大文字・小文字を正規化 |
| ドラッグ途中のツール変更がロールバックに巻き戻される可能性 | 未確定編集の取消後に新しいツール・階を設定 |

最初の5件は修正前にブラウザーテストで再現し、修正後に同じ手順で通過を確認した。

## UIの整理

- 「表示 → 表示設定」に共通・平面・3Dの設定をまとめ、メニューバーはコマンド選択に集中。
- 配置案内を配置条件の先頭へ移し、ラベルと入力欄を横並びにして縦スクロールを削減。
- スナップを常時表示。「入力補助」は必要時に展開。
- 表示フィルタで入力対象が隠れる場合は、表示設定への案内を表示。
- 英語の平面入力タブと断面ラベルを修正し、ヘルプも操作場所に合わせて更新。

## コードの責務

- UI.setPlacement / setTool: 入力条件・ツール変更の入口。
- ToolManager.restoreHistory: 履歴操作と未確定入力の取消。
- js/keyboard.js: CADショートカットを適用する条件。
- js/domain/placement.js: 面材の実際の入力方式。
- js/ui/menus.js: メニューの開閉・フォーカス・キー操作。
- js/ui/inspector.js: 右パネルのタブ制御。
- js/ui/placement-context.js: 配置案内と非表示状態の判定。
- js/ui/workspace.js: 画面上のコマンドと各機能の接続。

追加機能が増える際は、js/ui.jsに残る表示設定のバインドと部材別の配置条件フォームを独立させる余地がある。
ただし今回の不具合は上記の共通化で対応できるため、モデル保存形式や履歴の基盤の全面書き換えは行わない。

## 検証

ローカル検証は全件通過。

- npm run check: 単体474件、解析契約7件、バージョン整合、JavaScript/HTML/CSSの静的検査。
- npm run test:e2e: Chromium・Firefox・WebKitで各34件、合計102件。
- 768px幅の表示設定フォームでも全項目の編集と閉じる操作を確認。

回帰テストは修飾キー・IME、3Dからの入力、Undo/Redo、入力状態の同期、言語変更、表示フォーム、外壁確定、ドラッグ取消を対象とする。
既存のモデル生成・保存読込・解析連携のテストも実施した。
画面は1440px・1024px・768px幅、ダーク/ライト、日本語/英語を確認した。
GitHub Actionsは手動の最終Pages公開だけを実行し、CIワークフローは起動しない。
